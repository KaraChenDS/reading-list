# 读书清单 · 技术 PM 转商业

一个给自己用的单文件 PWA：把「技术型产品经理转经营者」的待读书单变成可执行的阅读引导——每本书的核心要点、可核查的原文出处、我的摘抄与批注、以及一条能看见的读书历程。

零依赖、零构建——整个 App 就是一个 `index.html`。

**线上地址：<https://karachends.github.io/reading-list/>**

---

## 一、怎么打开

**方式 1：线上地址（推荐）** 手机、iPad、电脑都直接打开同一个网址：

```
https://karachends.github.io/reading-list/
```

iOS Safari / Android Chrome 里 **分享 → 添加到主屏幕**，会像原生 App 一样全屏运行，并且**离线可用**（HTTPS 下 Service Worker 正常工作，断网也能翻要点、记笔记，联网后自动同步）。

**方式 2：本地服务**（改代码时用）

```bash
cd "做一些小应用/读书清单"
python3 -m http.server 8899 --bind 0.0.0.0
# 手机同 WiFi 打开 http://<电脑局域网IP>:8899/
```

> ⚠️ 局域网 http 是非安全上下文，Service Worker 不会注册——能装到主屏但**不能离线**，详见第八节。

**方式 3：直接双击 `index.html`**（`file://` 下已验证可用；只有 manifest 会因 CORS 被拒，不影响功能）

## 二、它是什么

四个页面：

| 页面 | 作用 |
|---|---|
| **书架** | 4 本书的卡片：封面色、作者、状态（未开始／在读／已读完）、要点完成度进度环 |
| **书籍详情** | 这本书对你的价值 → 阅读进度 + 「当前读到哪儿」→ 核心要点（可折叠）→ 读后感 |
| **历程** | 连续天数、累计打卡、已理解要点、摘抄数 + **近 12 周打卡热力图** + 按天分组的读书时间线 |
| **设置** | 主题、同步状态、导入导出、清空 |

**每个核心要点的结构**（这是这个 App 的核心设计）：

```
要点名称（如「坏战略的四个特征」）
├── 这是什么            —— 1-2 句定义
├── 为什么对你重要        —— 针对「技术型 PM 转经营者」的具体价值
├── 章节位置            —— 该读哪一部分
├── 可核查原文（N 条）    —— 英文原文 + 中译 + 出处链接 + 可信度标签 + 逐条 ⓘ 备注
├── 我的摘抄（N 条）      —— 读到好句子时自己录入，带页码
└── 我的批注            —— 自动保存
```

交互就是「读到一个就勾一个」：勾选要点 = 一次打卡，立刻出现在历程里。

## 三、书单与引用可信度（重要）

书单来自「技术型产品经理转商业」那份会话的精简推荐——**3+1 本**：

| 书 | 要点 | 书内逐字命中 | 二手转述 | 留空位 | 存疑 |
|---|---|---|---|---|---|
| 《认识商业》 | 12 | 17 | 0 | 0 | 5 |
| 《好战略，坏战略》 | 12 | 24 | 0 | 0 | 5 |
| 《跨越鸿沟》 | 12 | 10 | 2 | 4 | 7 |
| 《穷查理宝典》 | 11 | 16 | 0 | 2 | 5 |
| **合计** | **47** | **67** | **2** | **6** | **22** |

### 三种标注的含义

- 🟢 **原文 · 已核查** —— 已核对的逐字原文：
  - 《认识商业》《好战略，坏战略》《跨越鸿沟》通过 **Google Books 全文检索**在书内命中（`books.google.com/books/feeds/volumes?q="逐字短语"`）
  - 《穷查理宝典》通过 **Stripe Press 2023 官方免费全文版**核对
  - 少数几条是「两个相互独立的公开来源措辞完全一致」
- 🟡 **二手转述** —— 单一来源，或只有中译可核实，**不是逐字原文**
- ⬜ **留空位** —— 该要点**没有**可公开核查的原文。不硬凑，留给你读到原文时用「我的摘抄」填

每条引用下面的 ⓘ 备注会写明：命中了哪个版本、**有没有措辞差异**。

### 已经剔除的「常见错误引用」

核对过程抓出若干广为流传、但**原书并非如此**的句子，都收在各书底部的「存疑引用」折叠区里：

| 流传的说法 | 实际问题 |
|---|---|
| 「早期市场客户想要技术本身，主流客户想要完整产品」 | 不是摩尔的原话，是把书中两个命题压缩成的流行话术，语义有偏差 |
| 「摩尔提出了 whole product」 | 概念由 **Regis McKenna (1985)** 命名，摩尔是把它带火的人 |
| 「The essence of strategy is choosing what not to do」 | 出自 **Michael Porter 1996 年 HBR**，不是鲁梅尔特 |
| 「The best thing a human being can do…」 | 在《穷查理宝典》官方全文中**检索 0 次命中**，查不到一手出处 |
| 「睡前比早上起床时聪明一点点」 | 是 Stripe Press 的**出版方宣传语**，不是芒格原文 |
| 「Segment. Segment. Segment.」 | 书内查不到证据（同段只有 `big fish, small pond`） |

以及 9 处措辞差异，例如原书是 `kernel of **a** strategy`、`paths **into** the future`、
`some kind of change agent`、`every problem **tends to look pretty much** like a nail`、
`a simple, **basic** idea / take it **very** seriously`。引用这些句子时以 App 里的版本为准。

## 四、同步：设计成「无感知」

**你不需要做任何同步操作。** 没有「上传」「下载」按钮需要点（手动按钮被收进「设置 → 高级」里，作为兜底）。

### 自动行为

| 时机 | 动作 |
|---|---|
| 打开应用 | 静默拉取云端并合并 |
| 任何改动（勾要点 / 写摘抄 / 改批注 / 换状态） | 约 2.5 秒后静默上传 |
| 从后台切回页面 | 再拉一次（所以手机上刚记的，电脑上切回来就有） |
| 网络恢复 | 再拉一次 |
| 云端文件还不存在 | 自动用本机数据创建，完成首次引导 |

失败一律静默，只有**真的合并到了其他设备的更新**时才会弹一句提示。

顶栏右上角有一个 **🔄 手动刷新**按钮（拉取 + 回写，一次点击完成双向同步，带自转动画）。日常不需要点它——它的作用是**兜底**：网络不稳、或你刚从另一台设备同步完想立刻确认时用。

**一个容易漏掉的关键规则**：拉取合并之后，必须判断「本机是否比云端更全」，更全就**回写**。
否则一台**在连接之前就已经有本地记录**的设备会永远只拉不推，它的数据永远上不去——这正是「手机记了、电脑看不到」的典型症状。

### 配置是内置的

`owner / repo / path` 写死在应用里，用户不需要知道也不需要填：

```js
const SYNC_DEFAULTS = { owner:"KaraChenDS", repo:"reading-list-data", path:"reading-list.json" };
```

数据存在**私有**仓库 [`KaraChenDS/reading-list-data`](https://github.com/KaraChenDS/reading-list-data)，只有账号本人能读。

### 唯一需要做一次的事：在新设备上「连接」

每台设备第一次打开时，需要粘贴一次访问令牌。**之后永久无感。**

最省事的方式是**一键连接**——在电脑上生成一个带令牌的链接，发到手机/iPad 上点开一次即可：

```
https://karachends.github.io/reading-list/#t=这里换成你的令牌
```

> ⚠️ **把 `这里换成你的令牌` 这几个字整段替换掉**，换成 `github_pat_` 开头的那一整串（90+ 个字符）。
> **千万不要把说明里的占位字原样粘进去** —— 占位字里有中文，浏览器会拒绝发送含非 ASCII 的请求头并抛出 `TypeError`，看起来很像"网络不通"，实际上是令牌没填对。App 现在会在发请求前拦住这种情况并说明原因。

App 会从地址栏读走令牌、立刻把地址栏抹干净（`history.replaceState`），下次打开就是已连接状态。

也可以手动粘贴：**设置 → 访问令牌 → 连接并同步**。

### 为什么令牌不能也内置进代码（安全说明）

App 部署在 GitHub Pages 上，是一个**公开页面**——写进代码的任何东西都是公开的。如果把带写入权限的令牌内置进代码：

1. 任何访问这个页面的人都能查看源码、拿到你私有仓库的**写入**钥匙
2. 更现实的是：**GitHub 的机密扫描（secret scanning）会检测到公开仓库里的 PAT 并自动吊销它**，所以这条路技术上也不成立

所以安全的设计只有一种：**代码里不放密钥，密钥只存在每台设备的浏览器 localStorage 里**（键名 `dushu_sync_v1`），导出与同步载荷都会自动剥离它（已实测：`syncPayload()` 里不含令牌）。

> 令牌请用 **Fine-grained PAT**，只勾这一个仓库、只给 **Contents: Read and write** 权限——不要用 classic token 的 `repo` 全权限。

### 同步出问题怎么看

**设置**页会显示「上次同步 · x 分钟前」或「同步异常：具体原因」；**书架**在同步失败时顶部会出现红色横幅 + 重试按钮。

要精确定位断点，用 **设置 → 高级 → 连接诊断**，它会逐环节给出结论：

```
✅ 本机已保存令牌：github_pat_11AB…（共 93 字符）
○  同步目标：KaraChenDS/reading-list-data → reading-list.json
✅ 能否访问 api.github.com：HTTP 403（403 通常是限流，网络本身是通的），耗时 60 ms
✅ 读云端文件：HTTP 200，当前 815 字节
```

两种错误要分清，因为它们的原因完全不同：

| 文案 | 含义 |
|---|---|
| `下载失败 HTTP 401/403` | 令牌无效 / 权限不足 —— 去 GitHub 重新生成 |
| `连不上 api.github.com` | **网络层不通**（非令牌问题）。某些网络会单独阻断 `api.github.com`，即使 `github.io` 能打开；需要代理，或改用 Gitee 等国内可达的后端 |
| `令牌里有中文或其它非法字符` / `令牌只有 N 个字符` | 粘错了：填成了示例里的占位字，或没复制完整。App 会**在发请求前**拦下，不会误报成网络问题 |

> 排查顺序很重要：**令牌格式 → 网络可达 → 令牌有效 → 权限 → 仓库**。
> 早期版本把所有 `TypeError` 都当成"网络不通"，导致"粘了占位符"被误诊为"手机网络被墙"。连接诊断现在第一项就检查令牌格式。

### 合并规则

- **以「每本书」为单位**，取 `_ts` 较新的那一版（册内后写覆盖）
- **打卡记录按 `id` 去重合并**，两台设备的记录都会保留，不会丢
- **主题是设备级偏好**，不参与同步

### 数据结构

```js
{
  v: 1,
  books: {
    zhanlue: {
      status: "unread" | "reading" | "done",
      startedAt, finishedAt,
      currentWhere: "第 3 篇 · 营销 / P.128",   // 当前读到哪儿
      points:     { "zl-1": 1728530000000 },    // 要点 id → 勾选时间
      quotesRead: { "zl-1:0": 1728530000000 },  // 引用 id → 已读到时间
      notes:      { "zl-1": { text, ts } },     // 要点批注
      mine:       [ { id, pid, text, page, ts } ], // 我的摘抄
      review:     "整本书读后感",
      _ts: 1728530000000                        // 本册最后修改时间，用于合并
    }
  },
  events: [ { id, ts, type, bookId, text } ],   // 历程时间线
  theme: "auto" | "light" | "dark",
  _ts: 1728530000000
}
```

`events[].type`：`start` / `point` / `quote` / `finish` / `reread`。

**改代码后重新发布：**

```bash
cd "做一些小应用/读书清单"
git add -A && git commit -m "update" && git push
```

## 六、设计说明

```
index.html          单文件应用（HTML + CSS + JS 全内联，约 110KB）
  ├── BOOKS[]       书单内容数据（唯一需要改内容的地方，用 @BOOKS_START@ / @BOOKS_END@ 标记）
  ├── 状态与渲染       localStorage + 字符串模板渲染 + 事件委托
  ├── 云同步         GitHub Contents API（内置配置 / 打开即拉 / 改动即推 / 按册合并）
  └── PWA            manifest + Service Worker（network-first，跨域 API 不缓存）
manifest.webmanifest
sw.js               App Shell 缓存，cache 名 "dushu-v1"
icons/              icon-32/64/180/192/512/512-maskable/1024
```

**几个刻意的选择**

- **单文件、零构建**：双击就能跑，十年后也不会因为依赖腐烂而打不开
- **不用 IndexedDB**：数据量小（几十条），localStorage 足够且更简单
- **同步以「册」为合并单位**：比按字段合并可预测得多——你要的是「哪台设备最后改了这本书」，不是字段级 merge
- **渲染用整页重绘 + 事件委托**：没有虚拟 DOM，代码量小到能一眼读完
- **引用一律带出处与备注**：宁可显示「二手转述」和「留空位」，也不填一句看起来很像的假原文
- **密钥不进代码**：安全上唯一站得住的做法，见第四节

## 七、测试

用 Chrome headless + CDP 驱动真实浏览器，对**本地版与线上版都跑过**：

| 场景 | 覆盖 |
|---|---|
| `shelf` | 书架渲染、浅/深色切换、历程空状态 + 热力图（84 格对齐）、设置页；线上还验证了 **Service Worker 注册 + manifest/图标可访问** |
| `flow` | 开始阅读 → 填当前位置 → 展开要点 → 勾选已理解 → 标记原文已读到 → 添加摘抄 → 写批注 → **刷新后仍在** → 历程时间线 → 导出 → 标记读完 |
| `sync` | 配置已内置（页面上不再出现用户名/仓库名输入框）、空令牌的提示、无效令牌的 401 优雅处理、**令牌不进同步载荷**、跨设备导入合并（远端生效且本地不被覆盖）、断开后可恢复 |
| `bootstrap` | **`#t=` 一键连接**：令牌写入本机、地址栏被抹掉、设置页转为「已连接」且不再要求填令牌 |
| `slots` | 「没有可核查原文」时正确显示留空位；全书引用与可信度分布 |
| `desktop` | 1280px 下布局；390px 下无横向溢出 |

已验证：`file://`、局域网 `http://`、线上 `https://` 三种环境均正常运行；无 JS 异常。

### 测试如何与真实数据隔离

这套测试踩过坑，所以做了**物理隔离**：

1. 单独建了一个测试仓库 `reading-list-testdata`，测试**只**写它；
2. **在应用加载之前**就注入测试配置 —— 应用加载后约 700ms 会自己同步一次，如果那时配置还指着真实仓库，就已经写进去了；
3. 场景内只清 `dushu_v1`（应用数据），**不清整个 localStorage**，否则会把测试配置一起清掉、回落成真实仓库；
4. 每个场景前**断言**同步目标不是真实数据文件；
5. 监听 `Network.requestWillBeSent` 做**请求审计**，出现写真实仓库的 PUT 就报错；
6. 每轮测试用随机文件名，避免上一轮数据干扰。

每轮测试结束后都用 API 确认一遍：**真实数据仓库一次都没被写过**。

## 八、已知限制

- **每台设备要连接一次**：这是上面「安全说明」的直接后果——静态公开页面无法安全地持有密钥
- **局域网 http 下 Service Worker 不注册**：能装到主屏但不能离线（用线上 HTTPS 地址即可解决）
- **不支持附件**：摘抄是纯文本
- **同步以册为单位**：同一本书在两台设备上同时改，后改的那册会赢——但打卡记录按 id 合并，不会丢
- **中译本页码需自行核对**：《认识商业》第 10 版与第 12/13 版章节划分不同（前者 19 章、后者 20 章）；《穷查理宝典》中文译文多数是直译，**不是李继宏译本原文**
- **《跨越鸿沟》的「整体产品」措辞**：概念归属已确认（Regis McKenna），但逐字原文无法核实（该书没有全文检索），要精确引用需查纸本

## 九、这套做法已固化成 skill

同步这套东西踩过的坑（合并会丢数据、拉取不回写、测试污染真实数据、Pages 的 HTML 缓存、局域网不是安全上下文……）已经整理成一个可复用的 skill：

```
~/.dsh/skills/pwa-cloud-sync/SKILL.md
```

以后你说「给这个应用加多设备同步」，它会自动加载，不用再重新踩一遍。
