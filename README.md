# 读书清单 · 技术 PM 转商业

一个给自己用的单文件 PWA：把「技术型产品经理转经营者」的待读书单变成可执行的阅读引导——每本书的核心要点、可核查的原文出处、我的摘抄与批注、以及一条能看见的读书历程。

零依赖、零构建——整个 App 就是一个 `index.html`。

---

## 一、怎么打开

**方式 1：直接双击 `index.html`**（`file://` 下已验证可用；只有 manifest 会因 CORS 被拒，不影响功能）

**方式 2：本地服务 + 手机安装**（推荐日常使用）

```bash
cd "做一些小应用/读书清单"
python3 -m http.server 8899 --bind 0.0.0.0
```

手机与电脑连同一个 WiFi，浏览器打开 `http://<电脑局域网IP>:8899/`，
然后 **分享 → 添加到主屏幕**，就像一个原生 App（图标、全屏、离线可用）。

> ⚠️ 局域网 http 属于**非安全上下文**，Service Worker 不会注册——所以「添加到主屏幕」可以装，但**离线缓存不生效**，且电脑必须开机。想要随时随地打开 + 真正离线，见第五节。

**方式 3：部署到静态托管**（随时随地打开，推荐长期使用）

把 `index.html`、`manifest.webmanifest`、`sw.js`、`icons/` 传到任意静态托管即可，**不需要任何构建步骤**。详见第五节。

## 二、它是什么

四个页面：

| 页面 | 作用 |
|---|---|
| **书架** | 4 本书的卡片：封面色、作者、状态（未开始／在读／已读完）、要点完成度进度环 |
| **书籍详情** | 这本书对你的价值 → 阅读进度 + 「当前读到哪儿」→ 核心要点（可折叠）→ 读后感 |
| **历程** | 连续天数、累计打卡、已理解要点、摘抄数 + **近 12 周打卡热力图** + 按天分组的读书时间线 |
| **设置** | 主题、云同步、导入导出、清空 |

**每个核心要点的结构**（这是这个 App 的核心设计）：

```
要点名称（如「坏战略的四个特征」）
├── 这是什么            —— 1-2 句定义
├── 为什么对你重要        —— 针对「技术型 PM 转经营者」的具体价值
├── 章节位置            —— 该读哪一部分
├── 可核查原文（N 条）    —— 英文原文 + 中译 + 出处链接 + 可信度标签 + 逐条 ⓘ 备注
├── 我的摘抄（N 条）      —— 读到好句子时自己录入，带页码
└── 我的批注            —— 自动保存
```

交互是「读到一个就勾一个」：勾选要点 = 一次打卡，会立刻出现在历程里。

## 三、书单与引用可信度（重要）

书单来自「技术型产品经理转商业」那份会话的精简推荐——**3+1 本**：

| 书 | 要点 | 书内逐字命中 | 二手转述 | 留空位 | 存疑 |
|---|---|---|---|---|---|
| 《认识商业》 | 12 | 17 | 0 | 0 | 5 |
| 《好战略，坏战略》 | 12 | 24 | 0 | 0 | 5 |
| 《跨越鸿沟》 | 12 | 10 | 2 | 4 | 7 |
| 《穷查理宝典》 | 11 | 16 | 0 | 2 | 5 |
| **合计** | **47** | **67** | **2** | **6** | **22** |

### 三种标注的含义

- 🟢 **原文 · 已核查** —— 已经过核对的逐字原文：
  - 《认识商业》《好战略，坏战略》《跨越鸿沟》通过 **Google Books 全文检索**在书内命中（`books.google.com/books/feeds/volumes?q="逐字短语"`）
  - 《穷查理宝典》通过 **Stripe Press 2023 官方免费全文版**核对
  - 少数几条是「两个相互独立的公开来源措辞完全一致」
- 🟡 **二手转述** —— 单一来源，或只有中译可核实，**不是逐字原文**
- ⬜ **留空位** —— 该要点**没有**可公开核查的原文。不硬凑，留给你读到原文时用「我的摘抄」填

每条引用下面的 ⓘ 备注会写明：命中了哪个版本、**有没有措辞差异**。

### 已经剔除的「常见错误引用」

核对过程抓出若干广为流传、但**原书并非如此**的句子，都收在各书底部的「存疑引用」折叠区里：

| 流传的说法 | 实际问题 |
|---|---|
| 「早期市场客户想要技术本身，主流客户想要完整产品」 | 不是摩尔的原话，是把书中两个命题压缩成的流行话术，语义有偏差 |
| 「摩尔提出了 whole product」 | 概念由 **Regis McKenna (1985)** 命名，摩尔是把它带火的人 |
| 「The essence of strategy is choosing what not to do」 | 出自 **Michael Porter 1996 年 HBR**，不是鲁梅尔特 |
| 「The best thing a human being can do…」 | 在《穷查理宝典》官方全文中**检索 0 次命中**，查不到一手出处 |
| 「睡前比早上起床时聪明一点点」 | 是 Stripe Press 的**出版方宣传语**，不是芒格原文 |
| 「Segment. Segment. Segment.」 | 书内查不到证据（同段只有 `big fish, small pond`） |

以及 9 处措辞差异，例如原书是 `kernel of **a** strategy`、`paths **into** the future`、
`some kind of change agent`、`every problem **tends to look pretty much** like a nail`、
`a simple, **basic** idea / take it **very** seriously`。引用这些句子时以 App 里的版本为准。

## 四、数据与同步

### 存储

- 全部数据存在浏览器 **localStorage**，key 为 `dushu_v1`
- 同步配置（含 Token）存在 `dushu_sync_v1`
- **没有后端、没有账号、没有埋点**；Token 只存在你这台设备里，导出与同步内容都会自动剥离

### 数据结构

```js
{
  v: 1,
  books: {
    zhanlue: {
      status: "unread" | "reading" | "done",
      startedAt, finishedAt,
      currentWhere: "第 3 篇 · 营销 / P.128",   // 当前读到哪儿
      points:     { "zl-1": 1728530000000 },    // 要点 id → 勾选时间
      quotesRead: { "zl-1:0": 1728530000000 },  // 引用 id → 已读到时间
      notes:      { "zl-1": { text, ts } },     // 要点批注
      mine:       [ { id, pid, text, page, ts } ], // 我的摘抄
      review:     "整本书读后感",
      _ts: 1728530000000                        // 本册最后修改时间，用于同步合并
    }
  },
  events: [ { id, ts, type, bookId, text } ],   // 历程时间线
  theme: "auto" | "light" | "dark",
  _ts: 1728530000000
}
```

`events[].type` 取值：`start` / `point` / `quote` / `finish` / `reread`。

### 云同步（GitHub 私有仓库）

沿用我另两个 App 的做法：**GitHub Contents API + Fine-grained PAT**。

配置步骤（设置页里有同样的说明）：

1. GitHub 新建一个 **Private** 仓库，例如 `reading-list-data`（可勾选 Add a README）
2. Settings → Developer settings → Personal access tokens → **Fine-grained tokens**
3. Repository access 只选这个仓库；Permissions → **Contents: Read and write**
4. 把 Token 粘进「设置 → 数据与同步」，四项填好，点「保存并拉取」
5. 其他设备填同样四项，点「拉取云端」

**合并规则**（重要，避免互相覆盖）：

- **以「每本书」为单位**，取 `_ts` 较新的那一版（后写覆盖，但只在册内）
- **打卡记录按 `id` 去重合并**，两台设备的记录都会保留
- 改完 2.5 秒自动上传（可关）
- **主题是设备级偏好，不参与同步**

已实测：无效 Token 会被优雅提示（HTTP 401）而非崩溃；模拟另一台设备灌入数据后，远端状态与事件正确合并，**本地已有记录没有被覆盖**。

## 五、部署（想随时打开再读这节）

**关键区分——GitHub 在这里有两个完全不同的角色：**

| 用途 | 仓库 | 可见性 |
|---|---|---|
| 存放**这个 App 的代码**（要能打开它） | 一个静态托管 | **公开**（代码里没有你的任何数据） |
| 存放**你的读书数据** | 另一个仓库 | **私有**（只有你能读） |

所以：**如果你只想在家/办公室用同一个 WiFi，不需要部署**——用第一节的方式 2 就够了。
**如果你想在地铁上、在公司、在任何地方打开，就需要把 App 本身托管到公网**（这跟数据同步是两件事）。

三种免费方案：

**A. GitHub Pages**（最简单）

```bash
# 建议仓库名用 ASCII，避免 URL 里出现中文百分号编码
cd "做一些小应用/读书清单"
git init && git add . && git commit -m "读书清单 v1"
git branch -M main
git remote add origin git@github.com:<你的用户名>/reading-list.git
git push -u origin main
```

然后在仓库 Settings → Pages → Source 选 `main` / `root`，几分钟后访问
`https://<你的用户名>.github.io/reading-list/`。
免费账号的 Pages 要求仓库是 **public**——App 代码公开没问题，数据仍在私有仓库里。

**B. Cloudflare Pages / Vercel / Netlify**：支持**私有**源码仓库 + 免费 HTTPS，上传整个文件夹即可。

**C. 保持不变，只用局域网**：不部署，代价是电脑必须开机、同 WiFi。

> 部署后会多一个好处：**HTTPS 是安全上下文，Service Worker 能注册**，于是「添加到主屏幕」后真正离线可用（断网也能翻要点、记笔记，联网后自动同步）。

## 六、设计说明

```
index.html          单文件应用（HTML + CSS + JS 全内联，约 100KB）
  ├── BOOKS[]       书单内容数据（唯一需要改内容的地方，用 @BOOKS_START@ / @BOOKS_END@ 标记）
  ├── 状态与渲染       localStorage + 字符串模板渲染 + 事件委托
  ├── 云同步         GitHub Contents API（推送 / 拉取 / 合并）
  └── PWA            manifest + Service Worker（network-first，跨域 API 不缓存）
manifest.webmanifest
sw.js               App Shell 缓存，cache 名 "dushu-v1"
icons/              icon-32/64/180/192/512/512-maskable/1024
```

**几个刻意的选择**

- **单文件、零构建**：双击就能跑，十年后也不会因为依赖腐烂而打不开
- **不用 IndexedDB**：数据量小（几十条），localStorage 足够且更简单
- **同步以「册」为合并单位**：比按字段合并可预测得多——你要的是「哪台设备最后改了这本书」，不是字段级 merge
- **渲染用整页重绘 + 事件委托**：没有虚拟 DOM，代码量小到能一眼读完
- **引用一律带出处与备注**：宁可显示「二手转述」和「留空位」，也不填一句看起来很像的假原文

## 七、测试

用 Chrome headless + CDP 驱动真实浏览器跑了 5 组场景，全部通过：

| 场景 | 覆盖 |
|---|---|
| `shelf` | 书架渲染、浅/深色切换、历程空状态 + 热力图（84 格对齐）、设置页 |
| `flow` | 开始阅读 → 填当前位置 → 展开要点 → 勾选已理解 → 标记原文已读到 → 添加摘抄 → 写批注 → **刷新后仍在** → 历程时间线 → 导出 → 标记读完 |

| `desktop` | 1280px 下布局；390px 下无横向溢出 |

已验证：`file://` 与 `http://` 下均可正常运行；无 JS 异常。

## 八、已知限制

- **局域网 http 下 Service Worker 不注册**，所以「添加到主屏幕」后不能离线（部署到 HTTPS 即可解决）
- **照片/附件不支持**：摘抄是纯文本
- **同步以册为单位**：同一本书在两台设备上同时改，后改的那册会赢——但打卡记录按 id 合并，不会丢
- **中译本页码需自行核对**：《认识商业》第 10 版与第 12/13 版章节划分不同（前者 19 章、后者 20 章）；《穷查理宝典》中文译文多数是直译，**不是李继宏译本原文**
- **《跨越鸿沟》的「整体产品」措辞**：概念归属已确认（Regis McKenna），但逐字原文无法核实（该书没有全文检索），要精确引用需查纸本
